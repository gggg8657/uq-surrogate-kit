# uq-surrogate-kit

**A surrogate that also says when not to trust it.** Split-conformal
calibration, deep-ensemble and physics-residual uncertainty, and a speedup
harness — as a library that attaches to *any* simulator, not one model welded to
one PDE.

## KPI (verbatim from the portfolio board, project A4)

> **conformal 커버리지 90±2% · 추론 가속 ≥100× · OOD 탐지 AUROC ≥0.9**

**Status: `RUNNING`.** Was `UNREACHABLE` on the argument that ≥100× and a
calibrated interval were mutually exclusive. They were — but only because the
interval was built out of an ensemble, and that was our design decision, not a
property of the problem. A σ head emits mean and interval in **one forward
pass**, so that wall is gone.

**What the ✅ on clause 2 does and does not say.** It is *"24/24 measured fields
against this specified PCG implementation"* — not an established advantage over
an equivalently optimized reference. That reference is still a Python PCG loop
launching individual kernels; fused stencil kernels, cached grid-dependent
preconditioner data and graph-captured fixed-length PCG chunks are admissible
and unmeasured. At a 0.512 ms surrogate, a reference reaching **51.2 ms** on a
field takes the clause back under 100× on it, and the fastest field currently
solves in **60.3 ms** — a 15% margin. The three previous rounds of solver work
bought 1.28×, 1.08× and a selection fix.

The remaining failures are structural, not budgetary, and the OOD one is an
identity rather than a tuning gap — see [why](#the-shift-suite) and
[`WEEKEND.md`](WEEKEND.md). No number in this repository is typed by hand:
`scripts/check_prose_numbers.py` re-derives every headline in the prose files
from `runs/*.json` and CI fails if one has drifted.

## Why this is a kit and not an eval script

The uncertainty machinery is written against **nonconformity scores and tensors**
— never against a PDE. A calibrator sees `(pred, sigma, truth)` and nothing else;
a simulator plugs in through a four-method protocol. Two are shipped:

| simulator | what it is | where it runs |
|---|---|---|
| `sims.PDE2DSimulator` | 5 trained PDE families + 14 shifted variants, spectral / PCG / RK4 reference solvers | GPU |
| `sims.BatchReactorSim` | three coupled ODEs, RK4, a *multi-fidelity* surrogate (the same integrator at a coarser step) | CPU |

`tests/test_api.py` runs calibration, shift detection, error detection and the
timing harness end to end on the **reactor**, on CPU, in CI. That test is the
claim: if the kit only worked on the FNO corpus, it would fail.

```python
from uqkit import DeepEnsemble, UQSurrogate

uq = UQSurrogate(DeepEnsemble(members), score="field_max", alpha=0.1)
uq.calibrate(mean_cal, sigma_cal, truth_cal, inputs=a_cal)
uq.fit_detector(a_train)                       # in-distribution inputs only

lo, hi = uq.interval(mean, sigma)              # 90% simultaneous band
cov    = uq.evaluate(mean, sigma, truth)       # coverage + Wilson CI
trust  = uq.ood_score(inputs=a, kind="mahalanobis")
```

## What the kit measures, and the three ways that goes wrong

**1. "90% coverage" of a field is ambiguous.** Four scores are calibrated and
reported side by side, because the same interval covers 90% of *pixels* and far
fewer *fields*:

| score | certifies |
|---|---|
| `field_max` | the whole field inside `mean ± q·σ` — simultaneous, and the default |
| `pixel` | each pixel inside the band — marginal, the easy reading |
| `norm_ratio` | `‖error‖ ≤ q·‖σ‖` per sample |
| `rel_l2` | `rel-L2 ≤ q` — no σ at all, the baseline that shows what the ensemble buys |

**2. "OOD" is two questions.** *Shift detection* (did the input distribution
move?) and *error detection* (will the surrogate be wrong on **this** sample?).
A detector can be excellent at one and useless at the other, so they are scored
separately, and every shifted shard gets its own AUROC with a bootstrap
interval — an average over an easy shift and a hard one describes neither.

**3. A speedup without its conditions is a hardware benchmark.** `uqkit.bench`
will not emit a ratio without the device (same for both sides), the thread
count, per-sample *and* batched timings, and the surrogate's rel-L2 next to what
the reference solver was converged to. Three surrogate columns are timed:
one member, the full ensemble (what produces σ), and ensemble + residual check
— because the uncertainty costs roughly M forward passes and quoting the
single-member number while shipping the ensemble inflates the speedup by M.

## The shift suite

Fourteen shifted variants plus resolution, generated once by
`scripts/gen_data.py` and never seen by training, calibration or any detector
fit — grouped by *kind*, because they are not equally hard:

| kind | what moves | shards |
|---|---|---|
| `input_shift` | GRF roughness α, correlation length τ, amplitude — same operator | 20 |
| `param_oor` | a coefficient outside the trained range (Darcy contrast 3.0 vs 1.5; fractional order) | 4 |
| `unseen_operator` | a governing equation never trained on, presented under a task id the model *does* have | 3 |
| `resolution_*` | 128² and 256², from a model trained only at 64² | 10 |

`unseen_operator` is the adversarial case by construction: the sweep families
inherit their parent's input distribution exactly, so the *inputs are
statistically identical* and only the equation differs. Any input-space detector
is expected to sit at chance there. Whether the ensemble spread does too is a
measurement, and it is in `RESULTS.md`.

## Layout

```
uqkit/
  conformal.py   SplitConformal · GroupConformal · WeightedConformal · 4 scores
  ood.py         shift AUROC · error AUROC · bootstrap CIs
  bench.py       timing harness; refuses a ratio without its conditions
  features.py    resolution-comparable spectral features · Mahalanobis
  ensemble.py    DeepEnsemble (any callables, not just torch models)
  api.py         UQSurrogate · the Simulator protocol
  sims/          PDE2DSimulator (vendored solvers + FNO) · BatchReactorSim
scripts/         gen_data · train_member · train_ensemble.sh · eval_conformal
                 eval_ood · bench_speedup · measure_residual_floor · report
tests/           test_conformal · test_api · test_sims
```

## Reproducing

```bash
PY=~/miniforge3/envs/pdeno/bin/python
CUDA_VISIBLE_DEVICES=3 $PY scripts/gen_data.py --root data
bash scripts/train_ensemble.sh 60                     # 5 members, ~5 min each
CK=$(ls runs/m*/best.pt)
CUDA_VISIBLE_DEVICES=3 $PY scripts/eval_conformal.py --ckpts $CK
CUDA_VISIBLE_DEVICES=3 $PY scripts/eval_ood.py       --ckpts $CK
CUDA_VISIBLE_DEVICES=3 $PY scripts/bench_speedup.py  --ckpts $CK
CUDA_VISIBLE_DEVICES=3 $PY scripts/measure_residual_floor.py
$PY scripts/report.py                                 # regenerates RESULTS.md
$PY scripts/run_tests.py
```

Provenance: `uqkit/sims/pde2d.py` and `fno2d.py` are vendored from
[`pde-neural-operator`](https://github.com/gggg8657/pde-neural-operator) (same
author) so this repository is self-contained and CI-testable; the shift task
configs and the residual hook are new here. The weighted-conformal construction
follows the implementation in `wafer-tool-shift`, including its stated
approximation.
